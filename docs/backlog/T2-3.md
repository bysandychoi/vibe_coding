## 목적

이상 감지 시 발송될 알림의 저장 위치, 파일명 규칙, 그리고 내용 포맷을 설계한다.

**결정 내용 (이미 확정)**:
- **저장 위치**: `logs/alerts/` (저장소 루트 기준)
- **파일명 규칙**: `YYYYMMDD-HHMMSS_epochNNN.txt` (생성 시각 타임스탐프 + epoch 번호)
- **포맷**: 순수 텍스트

## 쉬운 설명

학습이 진행되다가 이상이 감지되면, 로컬 파일에 기록해두어 나중에 무엇이 일어났는지, 언제 감지되었는지를 추적할 수 있도록 한다.

예를 들어 2026-09-15 오후 2시 30분 22초에 epoch 42에서 gradient explosion이 감지되었다면:
- 파일 위치: `logs/alerts/20260915-143022_epoch042.txt`
- 내용: 이상 유형, 관련 수치, (Codex 판단 시) 판단 근거 등 평문 텍스트

## 필요한 입력

- **problem.md §6**: 알림 채널 및 내용 요구사항
- **problem.md §7**: 예시 1, 2, 3의 알림 형식 (텍스트 기반)
- **T2-1/T2-2/T2-4**: 임계치, 정상 run 판별, 이메일 취소 결정
- **프로젝트 구조**: 학습이 어디서 실행되는지, 로그 위치

## 결과물

**이미 확정된 결정 내용**:

```
알림 파일 저장 정책:

1. 저장 디렉터리
   경로: logs/alerts/ (저장소 루트 기준)
   예: C:\Users\bysan\iCloudDrive\바이브코딩 풀스택 개발\sdc-day1\logs\alerts\
   생성: 학습 스크립트 시작 시 (디렉터리가 없으면) 자동 생성 필요

2. 파일명 규칙
   형식: {YYYYMMDD}-{HHMMSS}_epoch{NNN}.txt
   예시:
     - 20260915-143022_epoch042.txt (2026-09-15 14:30:22, epoch 42)
     - 20260915-143022_epoch001.txt (2026-09-15 14:30:22, epoch 1)
   구성:
     - YYYYMMDD: 생성 날짜 (20260915)
     - HHMMSS: 생성 시각 (143022)
     - NNN: epoch 번호, 3자리 영점 패딩 (042)

3. 파일 포맷
   형식: 순수 텍스트 (.txt)
   이유: 평문이므로 나중에 수동으로 열어 읽기 쉬움

4. 내용 구조 (규칙 기반 이상)
   ---
   [타임스탐프]
   Anomaly Type: [gradient_explosion | nan_loss | inf_loss]
   Epoch: [번호]
   
   Details:
   [설명문 1-2줄]
   
   Metrics:
   [관련 수치]
   ---
   
   예:
   ---
   2026-09-15 14:30:22
   Anomaly Type: gradient_explosion
   Epoch: 42
   
   Details:
   gradient_norm exceeds threshold
   
   Metrics:
   gradient_norm=950.2
   threshold=120.5
   ---

5. 내용 구조 (AI/Codex 판단 이상)
   위와 동일하되, 추가로:
   
   Reason:
   [Codex 판단 근거 — JSON reason 필드 내용 평문화]
   
   예:
   ---
   2026-09-15 14:30:25
   Anomaly Type: entropy_collapse
   Epoch: 45
   
   Details:
   Entropy collapse detected by Codex CLI
   
   Reason:
   entropy가 지속적으로 급격히 감소하여 탐색이 거의 멈춘 상태로 판단됨.
   최근 12 epoch 동안 entropy 30→2로 약 93% 감소.
   ---

6. 다중 이상 동시 발생 처리
   같은 epoch에서 여러 유형의 이상이 감지되면:
   - 하나의 파일에 모든 이상을 기록 (파일명은 첫 번째 이상 유형 기준)
   - 또는 각 이상마다 별도 파일 생성
   현재 미정 — T2-7 구현 시 결정 필요
```

## 확인 질문

**결정 사항이 이미 확정되었으므로 추가 확인 질문은 없습니다.**

다만, 아래는 **구현 단계(T2-7 이후)에서 확인이 필요한 사항**입니다:

1. **다중 이상 동시 발생 처리**: 같은 epoch에서 규칙 기반 이상(예: gradient explosion)과 AI 판단 이상(예: entropy collapse)이 동시에 감지될 경우:
   - 하나의 파일에 모두 기록할 것인가?
   - 각각 별도 파일로 생성할 것인가?
   - 파일명은 첫 번째 유형 기준인가, 아니면 모두 포함할 것인가?
   현재 problem.md §9 "공통 지침"에 "한 텍스트 파일에 모든 유형을 함께 기록한다"고 했으므로 그대로 따를 것으로 예상.

2. **로그 보관 기간**: 알림 파일을 얼마나 오래 보관할 것인가? (무한 vs 일정 기간 후 자동 삭제)

3. **타임스탐프 정밀도**: `HHMMSS` (초 단위)가 충분한가, 아니면 밀리초(`HHMMSSfff`)가 필요한가? (같은 초에 여러 이상이 감지될 가능성)

# T1-3 — problem-reader 서브에이전트 작성

_source: backlog.json sha256=3410942…, schema=1.1 (as of this doc's generation)_

**상태**: in_review — 파일 수정은 완료했으나, 새 세션(agent 정의 캐시 갱신)에서 실제 동작 재호출 검증이 필요함.

## 목적

프로젝트 처음 입장한 사람(또는 기억을 새로 하는 사람)이 문제 정의를 빠르게 파악할 수 있도록, 서브에이전트 하나가 `problem.md`(또는 `problem-seed.md`)를 읽고 자동으로 요약하는 것. `.claude/agents/problem-reader.md`로 등록되어 Claude Code에서 호출 가능해야 한다.

## 쉬운 설명

이 프로젝트는 강화학습(RL) 스케줄러의 학습 중 문제를 조기에 감지하는 체계를 만드는 것인데, 문제 정의가 `problem.md`에 매우 상세하다(18줄). 새사람이 모든 걸 읽을 시간이 없을 때, "이 프로젝트 뭐하는 거야?"라고 물으면 `problem-reader` 서브에이전트가:

1. `problem.md`를 자동으로 읽고 (또는 없으면 `problem-seed.md`)
2. 핵심을 **구조화된 형태**(배경, 확인된 사실, 원인 가설, 범위, 결정사항, 입력/기대 결과 예시, 미결 질문)로 요약해서
3. 사용자에게 반환한다

**중요**: `problem-seed.md`는 RL 문제가 아니라 **다른 주제**(점검 기록 정리, 점검 데이터 취급)이므로, 폴백 시 "다른 주제이며 RL 문제 정의는 `problem.md`를 찾아야 한다"고 명시해야 한다.

## 필요한 입력

- `problem.md` — REINFORCE 스케줄러 학습 이상 감지 문제 정의 (18줄, 실제 존재)
- `problem-seed.md` — 초기 짧은 메모 (점검 기록 정리 주제, 폴백용)
- `.claude/agents/` 디렉토리 (에이전트 정의 저장소; critical-reviewer.md, backlog-explainer.md 등 기존 포맷 참고)

## 결과물

`.claude/agents/problem-reader.md` 파일:
- YAML 헤더: `name: problem-reader`, `description`, `tools: Read, Grep, Glob`, `model: haiku`
- 지시사항:
  - `problem.md` 존재 여부 확인 (Glob/Read) → 우선 읽기
  - `problem.md` 없으면 `problem-seed.md` 폴백 (단, **다른 주제**임을 명시)
  - 요약 구조 (7개 슬롯):
    1. **배경** (who/when/what problem, 2-3문장)
    2. **확인한 사실** (bullet: 알고리즘, 현재 로깅, 과거 사례)
    3. **원인 가설** (아직 미검증 가설을 "사실"에서 분리)
    4. **범위** (포함/제외 명시)
    5. **결정된 사항** (테이블 형태 결정사항 요약)
    6. **입력/기대 결과 예시** (실제 동작 시나리오)
    7. **미결 질문** (사용자가 결정해야 할 항목, 모두 나열)
  - 파일 끝에 "읽은 파일명 + 라인 수" 명시
  - 절대 파일 수정 없음 (Read/Grep/Glob만 사용)

사용자가 Claude Code에서 `/agents problem-reader`를 호출하면 이 요약을 즉시 받는다.

## 선행 작업

없음. T1-3은 T1-1, T1-2와 독립적으로 수행 가능하다. `problem.md` 또는 `problem-seed.md`가 존재하면 바로 작성 가능.

## 수행 순서

1. `problem.md`와 `problem-seed.md` 둘 다 실제 내용을 확인하여:
   - `problem.md`가 존재하고 RL 문제 정의를 담고 있는지
   - `problem-seed.md`가 다른 주제(점검 기록)를 다루는지
   - 각 파일의 섹션 구조 파악

2. `.claude/agents/critical-reviewer.md`, `.claude/agents/backlog-explainer.md` 기존 에이전트를 읽어 포맷 및 지시 방식 학습.

3. `.claude/agents/problem-reader.md` 작성:
   - YAML 헤더: `name: problem-reader`, `description: Reads and summarizes this repo's problem definition doc (problem.md, falling back to problem-seed.md...)`, `tools: Read, Grep, Glob`, `model: haiku`
   - 본문 지시:
     - `problem.md` 파일 존재 확인 → 있으면 읽고 요약
     - 없으면 `problem-seed.md` 읽기 (단, **다른 주제** 명시: "점검 기록 정리, 강화학습 스케줄러 이상 감지가 아님")
     - 요약 구조 7개 슬롯 명시 (각 슬롯에서 파일 내 해당 섹션을 참조)
     - 파일에 없는 내용은 창작하지 말 것
     - 요약 끝에 "읽은 파일: problem.md (XX 라인)" 또는 "읽은 파일: problem-seed.md (YY 라인)" 명시

4. 문서에 "Read/Grep/Glob만 사용하고 절대 파일 수정하지 않음" 명시.

5. npm run check 통과.

## done_when 확인 방법

**done_when 요구사항**: "/agents에서 problem-reader 등록 확인, 호출 시 problem.md 또는 problem-seed.md 요약 반환"

**구체적인 확인 방법**:

1. `.claude/agents/problem-reader.md` 파일이 존재하는지 확인한다.

2. 파일 헤더가 다음을 포함하는지 확인:
   - `name: problem-reader`
   - `tools: Read, Grep, Glob`
   - `model: haiku`

3. 파일 본문에 다음이 명시되어 있는지 확인:
   - `problem.md` 우선 읽기 로직
   - `problem-seed.md` 폴백 로직 (단, **다른 주제** 명시 필수)
   - 요약 구조 7개 슬롯: 배경, 확인한 사실, 원인 가설, 범위, 결정된 사항, 입력/기대 결과 예시, 미결 질문
   - "읽은 파일명 + 라인 수" 명시 지시

4. **새 세션에서** Claude Code의 `/agents` 명령을 실행하거나 `problem-reader`를 직접 호출하여:
   - problem-reader가 목록에 나타나는지 확인
   - 요약이 실제로 반환되는지 확인
   - 요약 구조가 문서의 7개 슬롯을 따르는지 확인 (배경, 확인한 사실, ...)
   - 각 섹션의 라벨이 file의 실제 제목과 일치하는지 확인
   - 파일이 수정되지 않았는지 확인

5. npm run check 통과.

## 알려한 한계 및 미확인 사항

**이 세션에서의 파일 수정 → 같은 세션 내 Subagent 캐시 미반영**

`.claude/agents/problem-reader.md`는 이 세션에서 수정(또는 처음 작성)되었으나, Claude Code의 Subagent 정의는 세션 시작 시점에 캐시되어 **같은 세션 내 파일 재저장 후 재호출에 변경이 반영되지 않는다.**

이전 세션에서 본 버전(또는 오래된 버전)이 캐시 메모리에 남아있을 수 있고, 현재 세션에서 problem-reader를 호출하면 수정 전 버전(낡은 라벨, 부분적인 슬롯)이 나올 가능성이 높다.

**해결책**: 새로운 세션을 시작한 후(Claude Code 재시작 또는 새 스레드) problem-reader를 호출해야 수정된 버전의 동작을 검증할 수 있다.

**따라서 이 태스크는 새 세션에서의 재호출 검증까지 포함해야 `done` 상태로 전환 가능하다.**

## 확인 질문

1. **새 세션에서의 재호출 검증 필수**: 현재 세션에서 파일은 수정했으나, Agent 캐시 때문에 실제 동작 검증은 불완전하다. 새 세션을 시작한 뒤(Claude Code 재시작 또는 새 스레드에서) problem-reader를 호출하고, 다음을 직접 확인해야 한다:
   - 요약의 7개 슬롯이 실제로 모두 포함되는가?
   - "입력/기대 결과 예시" 슬롯이 실제로 요약에 포함되는가? (예를 들어, rule-based immediate 사례 vs AI-judgment 사례 등)
   - 라벨들("배경", "확인한 사실", "원인 가설", "범위", "결정된 사항", "미결 질문")이 파일의 실제 제목과 일치하는가?
   - 문서 상단 또는 하단에 "읽은 파일: problem.md (18 라인)" 같은 명시가 나오는가?
   - 다른 주제(폴백 시) 메시지가 명확하게 나오는가?
   
   이상이 있으면 파일 내용을 재검토해 수정하고, 다시 새 세션에서 확인한다.

## 목적

REINFORCE 기반 강화학습 스케줄러 학습 중 발생하는 수치적 이상(gradient explosion, entropy collapse 등)을 조기에 자동 감지하는 시스템을 설계한다.

problem.md에는 배경, 현황, 결정된 사항이 정리되어 있으나, 구현을 위해 아직 결정하지 않은 7가지 미결 질문이 있다. 이 작업은 그 질문들을 해결하고 설계를 구체화하는 것이다.

## 쉬운 설명

현재 학습 스케줄러의 문제 발생을 알아차리는 방식:
- 개발자가 주기적으로 entropy/reward 로그를 눈으로 확인
- GPU 제약으로 인해 문제를 반나절 이상 지난 후에야 인지
- 누가 파라미터 설정을 잘못했는지, 망 설계가 잘못됐는지 구분 어려움

목표: 문제 발생 시 **늦어도 50 epoch 또는 2시간 이내**에 자동으로 감지하고 알림 발송.

감지 대상:
- **규칙 기반** (즉시): NaN/Inf loss, gradient explosion
- **AI 판단** (Codex CLI, 수 초~수십 초): gradient vanishing, entropy collapse, loss-reward 불일치

## 필요한 입력

- `problem.md` — 현황/결정된 사항/미결 질문 정리

- 기존 REINFORCE 구현의 로깅 방식 (policy loss, gradient norm 추가 가능 여부)

## 결과물

T2의 7가지 하위 작업 완료 시:

2. **T2-2**: "정상 run" 판별 기준 정의 (사람의 관찰 vs 자동 기준)
3. **T2-3**: 알림 파일 저장 위치/파일명/포맷 (예: `alerts/2025-09-15_epoch-42_gradient-explosion.json`)
4. **T2-4**: 이메일 발송 설정 (계정, 인증 방식)
5. **T2-5**: Codex CLI 판단 기준 가이드 (gradient vanishing 판정 방법, entropy collapse 판정 방법 등)
6. **T2-6**: 체크 주기 조절 방식 (예: `python scheduler.py --check-interval 10` 또는 설정 파일)

## 수행 순서

1. **T2-7 (먼저)**: 기존 entropy/reward 로그 파일 형식 확인
   - 파서가 읽을 수 있는 형태인지 검증

2. **T2-1**: gradient explosion 임계치 산출 방식 결정
   - 정상 run 5회 기준으로 평균±표준편차 vs 최댓값 vs percentile 중 선택

3. **T2-2**: "정상 run" 5회 판별 기준 결정
   - 사람이 직접 보고 판단 vs 자동 기준(예: 처음 N epoch 동안 손실 감소)

4. **T2-3**: 알림 텍스트 파일 저장 방식 설계
   - 디렉터리, 파일명 규칙(타임스탐프 포함), 포맷(JSON/TXT)

5. **T2-4**: 이메일 설정 확정
   - 발신 계정(Gmail/Outlook 등), 인증 방식(SMTP, 앱 비밀번호, OAuth 등)

6. **T2-5**: Codex CLI 판단 기준 작성
   - T2-1, T2-2 결과를 바탕으로 gradient vanishing/entropy collapse/loss-reward 불일치 판정 기준 문서화

7. **T2-6**: 체크 주기 조절 방식 결정
   - 실행 시 인자 vs 설정 파일 vs 환경 변수

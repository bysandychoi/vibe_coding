# T1-2 — /inspection-check 커맨드 작성

_source: backlog.json sha256=3410942…, schema=1.1 (as of this doc's generation)_

## 목적

Claude Code에서 사용할 수 있는 슬래시 커맨드 `/inspection-check`를 `.claude/commands/inspection-check.md`로 구현한다. 이 커맨드는 `data/inspection.csv`를 읽어서 메모 누락 행을 자동으로 감지하고 보고한다. `.claude/rules/data-handling.md`의 규칙을 따른다.

## 쉬운 설명

점검 데이터의 품질 관리를 자동화하는 것이다. 점검 기록에서:
- **OK** (문제 없음): 메모가 없어도 괜찮음
- **NG** (문제 있음): 반드시 조치 내용을 `action_note`에 기록해야 함

이 커맨드는 NG인데 메모가 없는 행을 찾아서 보고한다. 절대 파일을 수정하지 않는다 — 읽기만 한다.

## 필요한 입력

- `data/inspection.csv` — 보호된 교육용 원본 데이터 (equipment_id, result, action_note 컬럼)
- `.claude/rules/data-handling.md` — 메모 누락 판정 규칙
- `.claude/commands/` 디렉토리 (슬래시 커맨드 정의 위치)

## 결과물

`.claude/commands/inspection-check.md` 파일:
- YAML 헤더: `description`, `allowed-tools: Read`
- CSV 읽기 및 판정 로직:
  - `action_note` 앞뒤 공백 제거(trim) 및 따옴표 제거 절차
  - `result=NG` and trim 후 빈 문자열 → 메모 누락
  - `result=OK` → 항상 정상 (메모 규칙 미적용)
  - `result` 이 OK/NG 둘 다 아님 → 별도 "확인 필요" 목록으로 보고

- 결과 서식: 메모 누락 / 정상 / 확인 필요 세 범주로 구분 보고

사용자가 `/inspection-check`를 실행하면 현재 CSV에서 메모 누락을 즉시 감지해 보고받는다.

## 선행 작업

없음. T1-2는 독립적으로 수행 가능하다. (T1-1은 Hook 검증용이고, T1-2는 기능 구현이므로 서로 의존하지 않음)

## 수행 순서

1. `.claude/rules/data-handling.md`를 읽고 메모 누락 규칙을 명확히 이해한다:
   - "result가 NG이고 action_note의 앞뒤 공백을 제거한 값이 비면 메모 누락"
   - "OK 행에는 이 메모 필수 규칙을 적용하지 않는다"
   - "허용 값 이외의 result가 나오면 임의로 OK 또는 NG로 바꾸지 않고 질문한다"

2. `.claude/commands/` 폴더 구조와 기존 커맨드 포맷을 확인한다.

3. `inspection-check.md` 파일을 작성한다:
   - YAML 헤더: description, allowed-tools=Read
   - CSV 읽기 로직:
     - 헤더 파싱: equipment_id, result, action_note
     - 각 필드의 따옴표 제거 및 trim
   - 판정 로직:
     - result=NG & trim(action_note)="" → 메모 누락 수집
     - result=OK → 메모 필수 규칙 미적용
     - result이 OK/NG 외 → 별도 "확인 필요" 목록에 추가
   - 결과 포맷:
     - **메모 누락**: equipment_id 목록 (없으면 "메모 누락 없음")
     - **정상(NG, 메모 있음)**: 참고용 equipment_id 간단 나열
     - **확인 필요**: result 값이 이상한 행의 구체적 정보와 사용자 질문

4. `.claude/rules/data-handling.md` 및 현재 `data/inspection.csv`를 읽어 로직을 검증한다.

5. `.claude/commands/inspection-check.md` 파일 내에 "허용값(OK/NG) 가정이 `.claude/rules/data-handling.md`에 정의되지 않았으므로 현재 샘플 데이터 기준으로 OK/NG로 가정한다"고 명시한다.

6. npm run check 통과.

## done_when 확인 방법

**done_when 요구사항**: "샘플 CSV(EQ-002, EQ-003 메모 누락)에서 올바르게 검출"

**구체적인 확인 방법**:

1. `.claude/commands/inspection-check.md` 파일이 존재하는지 확인한다.

2. 파일 내용에 다음이 포함되어 있는지 확인:
   - `allowed-tools: Read` 명시 (파일 수정 불가)
   - 따옴표 제거 및 trim 절차 설명
   - 메모 누락 판정 로직: `result=NG` and (trim 후 빈 문자열)
   - OK 행 예외 처리: 메모 없어도 정상
   - 허용값 외 result 처리: 임의로 정규화하지 말고 보고

3. `/inspection-check` 커맨드를 실행(또는 문서 로직을 `data/inspection.csv`에 적용)하여:
   - EQ-002와 EQ-003이 메모 누락으로 검출되는지 확인
   - OK 행들은 정상으로 분류되는지 확인 (메모 포함/미포함 무관)
   - 메모가 있는 NG 행은 "정상" 범주에 들어가는지 확인

4. `data/inspection.csv` 파일 자체가 수정되지 않았는지 확인한다 (Read 도구만 사용).

5. npm run check 통과.

## 확인 질문

1. **허용값 정의 미확정**: `.claude/rules/data-handling.md`는 `result` 필드의 허용값 목록을 정의하지 않는다(라인 6에 "허용 값 이외의 result가 나오면...질문한다"라고만 명시). 현재 커맨드는 샘플 데이터(`OK`/`NG`)를 기준으로 이 둘을 가정하지만, 실제 운영 중에 다른 값(예: `OK_WITH_NOTES`, `FAIL`, 또는 대소문자 변형 `ng`, `Ok`)이 나올 수 있는가? 그렇다면 `.claude/rules/data-handling.md`에서 명시해 주거나, 커맨드 테스트 시 확인해야 한다.

2. **따옴표 처리의 다양성**: 현재 커맨드는 큰따옴표 기준으로 가정하는데, 실제 CSV 생성 환경에서 작은따옴표, 이스케이프 문자(`\"`), 또는 따옴표 없이 스페이스만으로 감싼 경우가 나올 수 있는가? 그렇다면 샘플 CSV 검토 또는 CSV 파생 규칙을 명시해야 한다.

# T1-4 — /hook-check 커맨드로 보호 파일 Hook 확인 실습

_source: backlog.json sha256=d127ba6998c2107c468aa977184b2066d43ba8261112ed47659c2441aa37406c, schema=1.1 (as of this doc's generation)_

## 목적

`.claude/settings.json`에 설정된 Hook 규칙이 `data/inspection.csv`를 실제로 보호하는지 직접 실행·시연하고, 그 과정을 체계적으로 문서화하기 위함입니다. 이를 통해 프로젝트의 핵심 데이터 무결성 보호 메커니즘이 실제로 작동함을 검증합니다.

## 쉬운 설명

프로젝트 저장소(git이 아님)에는 중요한 파일 `data/inspection.csv`가 있습니다. 이 파일이 실수로 삭제되거나 수정되면 복구할 방법이 없으므로, `.claude/settings.json`에서 Hook이라는 자동 차단 기능으로 보호하고 있습니다.

이 태스크는 그 Hook이 실제로 작동하는지 여러 방법으로 시도해보면서 확인하는 실습입니다. 예를 들어:
- Edit/Write 도구로 파일을 고쳐보려 하면 → 차단됨
- Bash에서 `sed` 명령으로 파일을 수정하려 하면 → 차단됨
- 다른 CSV 파일도 같은 방식으로 보호되는지 확인 → 보호됨
- 다른 폴더의 파일은 차단 없이 정상 처리되는지 확인 → 정상 처리됨

모두 확인한 후 원본 파일이 손상되지 않았는지 재확인합니다.

## 필요한 입력

- `.claude/settings.json` — Hook 규칙 정의
  - `permissions.deny`: `Edit|Write|NotebookEdit` on `data/*.csv`, `Bash(rm data/*.csv)`, `Bash(mv data/*.csv *)`
  - `PreToolUse` Hook 스크립트: `inspection.csv` 문자열 포함 여부로 Bash 명령 차단
- `data/inspection.csv` — 보호 대상 원본 파일
- `.claude/commands/hook-check.md` — 이 커맨드의 정의서

## 결과물

- `.claude/commands/hook-check.md` — 보호 파일 Hook 검증 절차를 정의한 커맨드 파일
- 실행 증거
  - Edit 시도 시 `Edit(data/*.csv)` deny 메시지
  - Write 시도 시 `Write(data/*.csv)` deny 메시지
  - Bash `sed` 시도 시 `BLOCKED: ...` 메시지 및 exit 2
  - Bash `echo > data/inspection.csv` 시도 시 `BLOCKED: ...` 메시지 및 exit 2
  - `data/sample.csv` Write 시도 시 `Write(data/*.csv)` deny 메시지 (다른 csv도 보호됨)
  - 스크래치 폴더의 임시 파일은 차단 없이 정상 처리
  - 실습 전후 `data/inspection.csv` 내용 완전히 동일함 확인

## 선행 작업

- **T1-1 (Windows Hook 검증)**: 이 태스크보다 먼저 Windows 환경에서 Hook의 기본 동작(exit 2 차단)이 검증되어야 합니다.

## 수행 순서

1. **0단계 — 원본 기록**: `data/inspection.csv`를 Read 도구로 읽어 전체 행 수와 내용을 기록해 둡니다(이후 단계에서 파일이 변경되지 않았는지 비교할 기준).

2. **1단계 — Edit/Write 경로 차단 확인**:
   - Edit 도구로 `data/inspection.csv`에 사소한 변경(예: 한 줄 추가)을 시도 → `Edit(data/*.csv)` deny 메시지로 차단됨
   - Write 도구로 같은 파일에 새 내용을 덮어쓰기 시도 → `Write(data/*.csv)` deny 메시지로 차단됨
   - 이 두 차단은 Hook 스크립트가 아니라 `permissions.deny` 계층에서 일어남(경로 기반 차단)

3. **2단계 — Bash Hook 스크립트 차단 확인**:
   - `sed -i 's/OK/OK/' data/inspection.csv`를 시도 (되돌릴 수 있는 무해한 치환) → `BLOCKED: ...` 및 exit 2로 차단됨 (토큰 매칭 분기)
   - `echo test > data/inspection.csv`를 시도 (리다이렉트) → `BLOCKED: ...` 및 exit 2로 차단됨 (리다이렉트 분기)
   - `rm data/inspection.csv`와 `mv data/inspection.csv ...`는 **실행하지 않음** — `permissions.deny`에도 이미 등록되어 있어 Hook 이전 단계에서 차단됨

4. **3단계 — 경계 대조군 (data 폴더 내 다른 csv)**:
   - `data/sample.csv` 같은 새 파일을 Write로 만들려고 시도 → `Write(data/*.csv)` deny로 차단됨
   - Hook은 `inspection.csv` 이름만 검사하지만, `permissions.deny`는 `data/*.csv` 전체를 보호함을 확인

5. **4단계 — 무관한 파일 대조군**:
   - 스크래치 임시 폴더(C:\Users\bysan\AppData\Local\Temp\claude\...) 안의 파일에 같은 시도를 반복 → 차단 없이 정상 처리됨
   - **주의**: 이 파일 이름에 `inspection.csv`라는 문자열을 포함시키지 않음 (Hook은 경로가 아니라 명령 문자열 안의 이름만 봄)

6. **5단계 — 원본 무결성 재확인**: `data/inspection.csv`를 다시 Read로 읽어 0단계 기록과 완전히 동일함을 확인합니다.

7. **6단계 — 결론 정리**:
   - Edit/Write 경로는 `permissions.deny`가 경로 기반으로 차단
   - Bash 경로는 Hook 스크립트가 명령 문자열 기반으로 차단
   - `data/*.csv` 전체는 `permissions.deny`로 보호, `data/inspection.csv`만 추가로 Hook의 대상
   - `data/` 밖의 파일은 차단되지 않음

## done_when 확인 방법

**done_when**: 
- `data/inspection.csv`에 대해 Edit·Write(permissions.deny)와 Bash Hook의 리다이렉트/토큰 두 분기(비파괴적 명령으로) 각각 차단 확인
- `data` 폴더 내 다른 csv도 permissions.deny로 차단됨을 확인
- `data` 폴더 밖 무관한 파일은 차단 안 됨을 확인
- 실습 전후 원본 내용 동일함을 확인

**확인 방법**:
1. `.claude/commands/hook-check.md` 파일의 0~6단계 내용이 모두 구현되어 있는지 읽기
2. 각 단계별 실행 증거(시도 출력, 차단 메시지) 확보
3. `data/inspection.csv` Read 결과로 원본 내용이 변경되지 않았음 확인
4. `npm run check` 실행 — 문법 검사와 길이 제한 통과 확인

**2. 초안의 Critical 안전성 문제 및 해소**

원래 이 커맨드의 초안에는 다음과 같은 지시가 있었습니다:
- "되돌릴 수 없는 명령(`rm data/inspection.csv`, `mv data/inspection.csv ...`)을 직접 실행해 보라"

critical-reviewer가 **Critical 수준 지적**을 제기했습니다:
> "이 저장소는 git이 아니라 삭제되면 복구 수단이 없는데, Hook이 어떤 이유로든 안 걸리면 영구 손실이다"

결과적으로 모든 되돌릴 수 없는 명령을 비파괴적 명령으로 교체했습니다:
- `rm` → `sed -i 's/OK/OK/' data/inspection.csv` (내용 자체는 바꾸지 않는 무해한 치환)
- `mv` → `echo test > 리다이렉트` (파일 내용 쓰기)

그리고 위 두 명령(`rm`, `mv`)은 `permissions.deny`에도 등록되어 있다는 사실을 설명으로만 언급하고 실행하지 않도록 명시했습니다. (`.claude/commands/hook-check.md` 10줄)

**3. 0단계 사전 기록의 중요성**

0단계에서 반드시 원본을 먼저 읽고 기록하는 절차를 맨 앞에 배치했습니다. 이는 만일의 사태 시 복구 기준이 될 수 있도록 하기 위함입니다. (`.claude/commands/hook-check.md` 8줄)
